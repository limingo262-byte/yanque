# 访问页面提示没有权限或无权访问

关键词：没有权限, 无权访问, 403, BusinessException, PermissionInterceptor, 权限, 菜单, 角色, permission, role

## 适用场景

用户已经能登录系统，但访问某个页面或接口时提示“没有权限”“无权访问当前资源”或返回 403。该问题通常不是 Token 缺失，而是 RBAC 权限、角色菜单、接口权限编码或拦截器判断不通过。

## 建议排查步骤

1. 先用 `query_yanque_sls_logs` 按时间范围检索 `无权访问`、`403`、`BusinessException`、`PermissionInterceptor`，确认本次请求是否被权限拦截器拒绝。
2. 如果日志里有 guid、traceId、requestId 或用户标识，用同一标识扩展上下文，确认是否存在“Token 为空”“未登录”等认证失败信息。
3. 用 `run_repository_command` 检索 `PermissionInterceptor`、`preHandle`、`无权访问当前资源`，读取拦截器附近代码，判断拒绝发生在 Controller 前还是业务方法里。
4. 用 `list_data_sources` 找到 YanQue 业务库，再用 `query_data_source` 只读查询用户、角色、菜单、权限关联表。只查必要字段，SQL 必须带 LIMIT。
5. 对比页面或接口需要的权限编码与用户实际拥有的角色权限，确认是未分配角色、角色未绑定菜单、菜单权限编码不一致，还是管理员后台数据异常。

## 常见候选原因

- 用户登录成功，但账号未绑定具备该页面权限的角色。
- 角色存在，但角色菜单或角色权限关联缺失。
- 前端菜单能看到页面，后端接口权限编码没有同步，导致接口被拦截。
- 权限拦截器没有打印 URI、用户和权限编码，日志只能看到 403，需要结合源码和数据库核验。

## 可参考查询方向

- 用户表：按手机号、用户名、用户 ID 查询账号状态。
- 角色关联表：查询该用户绑定了哪些角色。
- 角色权限或菜单关联表：查询角色是否拥有目标菜单或接口权限。
- 菜单/权限表：按页面路径、按钮编码或权限标识检索。

## 输出建议

结论要区分“认证失败”和“授权失败”。如果日志显示 `PermissionInterceptor` 抛出 `BusinessException: 无权访问当前资源`，优先判断为授权失败。若数据库确认角色缺少目标权限，建议运营或管理员补角色/菜单权限；若权限数据正确但仍被拒绝，建议研发检查权限编码、路径匹配和拦截器日志增强。
