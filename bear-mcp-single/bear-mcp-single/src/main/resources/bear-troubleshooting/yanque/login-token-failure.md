# 登录失败、Token 为空或会话失效

关键词：登录失败, Token不能为空, token, 401, 未登录, 用户名称和用户密码不正确, Authentication, Login, Authorization

## 适用场景

用户反馈无法登录、接口提示 Token 不能为空、页面跳登录页、用户名密码不正确。该类问题需要先区分认证失败、会话过期、前端未带请求头，以及账号数据异常。

## 建议排查步骤

1. 用 `query_yanque_sls_logs` 检索 `Token不能为空`、`用户名称和用户密码不正确`、`登录失败`、`401`、`Authorization`。
2. 如果是 Token 为空，继续查同一 guid/traceId 周边日志，确认是否前端请求未携带 Token，还是登录接口本身失败。
3. 用 `run_repository_command` 检索登录 Controller、认证拦截器、Token 校验逻辑和错误文本。
4. 必要时通过 `query_data_source` 按用户名或手机号只读查询账号状态、密码更新时间、是否禁用。不要查询或输出密码哈希以外的敏感字段。
5. 若前端页面中文乱码或菜单异常，优先怀疑数据库字符集或数据源覆盖过程，再检查前端编码。

## 常见候选原因

- 用户未登录或 Token 过期，访问业务接口被认证拦截。
- 前端请求没有携带 Authorization/Token 请求头。
- 用户名或密码错误，登录接口没有签发 Token。
- 账号被禁用或数据库用户数据被覆盖。
- 数据库字符集/导入问题导致中文配置或账号信息异常。

## 输出建议

明确区分“认证失败 401/Token 问题”和“授权失败 403/权限不足”。如果日志只有 Token 为空，不要说是角色权限问题；如果日志已经进入 PermissionInterceptor 并抛无权访问，再转到权限排障。
