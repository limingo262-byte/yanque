# 提交订单失败或订单状态异常

关键词：提交订单, 下单, 订单失败, order, 订单, 支付, product, course, student, 订单状态, 库存, 金额

## 适用场景

运营反馈用户提交订单失败、支付后状态不对、订单存在但后续业务关系没有生成。用户通常只能描述“下单失败”“付款成功但没开通课程”“订单看不到”，需要从日志、订单表、支付/产品/课程关系表一起确认。

## 建议排查步骤

1. 先用 `query_yanque_sls_logs` 在反馈时间前后检索 `订单`、`提交订单`、`支付`、`order`、`BusinessException`、`ERROR`。
2. 从日志中提取订单号、用户 ID、手机号、商品 ID、traceId/guid。没有订单号时，用用户和时间窗口去数据库只读核验。
3. 用 `run_repository_command` 检索订单创建、支付回调、课程开通相关 Service、Mapper 和异常信息，只读取最小相关代码片段。
4. 用 `query_data_source` 查询订单主表、订单明细、支付记录、用户课程/产品关联表，确认业务状态停在哪一步。SQL 只允许 SELECT，限制字段和 LIMIT。
5. 把“日志发生了什么”“代码在哪个条件分支拒绝”“数据库当前状态是什么”三者对齐后再下结论。

## 常见候选原因

- 商品、课程或套餐配置缺失，导致订单创建时校验失败。
- 用户重复提交，订单幂等或唯一约束导致第二次失败。
- 支付成功但回调未成功处理，订单状态和课程开通状态不一致。
- 订单状态已经成功，但前端或查询条件过滤导致运营页面看不到。
- 本地和服务器数据库数据不一致，尤其是中文或配置字段乱码时，前端可能显示异常或权限/菜单匹配失败。

## 可参考查询方向

- 订单主表：按订单号、用户 ID、创建时间查订单状态、金额、商品 ID。
- 支付记录表：按订单号查支付渠道、回调状态、回调时间、错误原因。
- 商品/课程表：查商品是否上架、课程是否启用、关联关系是否完整。
- 用户课程/产品关联表：查支付后是否生成权益。

## 输出建议

如果没有真实失败日志，可以明确说明“当前证据没有找到失败请求”，再用数据库状态说明未能确认的部分。不要只根据历史排障知识断言原因；必须给出日志、源码或数据库证据。
